# 문서 관리

[English](documentation-plan.md)

이 문서는 저장소의 문서 구조와 갱신 절차를 정의합니다. 현재 적용하는 절차입니다. 구현 상태는 [기능 상태](features.ko.md)에서 관리합니다.

<a id="ownership"></a>
## 정본 문서

각 주제에는 영어 정본 하나와 `.ko.md` 번역 하나를 관리합니다. [목록](documentation-manifest.json)은 모든 공통 Markdown 문서와 주제를 등록합니다. 각 구현 패키지는 자체 문서를 등록하며 공통 검사기는 두 단계 모두 검사합니다. 다른 문서는 같은 규칙을 반복하지 않고 정본 주제로 연결합니다.

| 위치 | 내용 |
| --- | --- |
| `README.md` | 프로젝트 소개, 최소 시작 절차, 문서 링크 |
| `docs/spec/` | 승인된 동작, 구조, API 계약, 인수 기준 |
| `docs/features.md` | 구현 상태, 검증 근거, 배포 상태 |
| `docs/operations/` | 현재 설치, 실행, 검증, 게시 절차 |
| `CHANGELOG.md` | 실제 변경, 원인, 검증 |
| `docs/plans/` | 승인 대기 제안 |
| `benchmarks/` | 재현 가능한 성능 비교와 벤치마크 입력 |
| `AGENTS.md` | 개발 절차와 필수 검사 |
| Git 외부 | 개인 선호, 대화 맥락, 로컬 인증 및 백업 정보 |

명세는 계약을 설명합니다. 기능 기록은 구현된 동작을 설명합니다. 배포 기록은 확인한 게시 결과를 설명합니다. 각 상태는 독립적으로 관리합니다.

<a id="updates"></a>
## 갱신 절차

1. 코드를 변경하기 전에 해당 명세를 읽습니다.
2. 방향이 바뀌면 명세부터 갱신하고 미구현 부분을 명시합니다.
3. 동작 변경, 관련 문서, 기능 상태, 변경 기록을 같은 변경에 포함합니다.
4. 영어와 한국어를 함께 수정합니다. 정보, 명령, 링크, 상태 값이 같은지 비교합니다.
5. 변경된 파일을 대상으로 필요한 검사를 실행합니다. 다른 소스 파일의 결과를 현재 검증 근거로 사용하지 않습니다.
6. 원격 소스, 릴리스 또는 패키지 결과를 확인한 후 게시 상태를 기록합니다.
7. 관련 개인 메모리를 Git 외부에서 갱신합니다.

제안을 승인한 후에는 명세를 갱신하고 제안 문서를 제거합니다. 기존 규칙이 승인된 계약이나 확인된 동작과 충돌하면 규칙을 수정합니다.

<a id="checks"></a>
## 문서 검사

`make docs-check`는 등록된 문서 쌍, 로컬 링크 대상과 앵커, 섹션 식별자 및 실행 코드 블록의 일치, 한국어 번역 기준 해시, 필수 기능 항목, 검증 근거 링크, 현재 검증 소스 해시를 검사합니다. 공개 문서와 보고서에 로컬 홈 디렉터리 경로가 포함돼도 실패합니다.

한국어 파일의 `source-sha256` 주석은 번역을 검토한 영어 개정본을 기록합니다. 번역 검토 후에만 갱신합니다. 해시 일치는 번역의 정확성을 증명하지 않습니다. 검사기는 외부 사이트의 접속 가능 여부나 문장의 의미를 검증하지 않으며, 코드와 테스트 결과를 읽고 확인해야 합니다.

`make check`는 검증기와 문서 검사기 테스트, 등록된 모든 JSON 구현, `make docs-check`를 실행합니다. [PIE 검증](operations/validation.ko.md#pie)은 별도의 빌드와 공통 사례 결과를 기록합니다. 호스팅 CI는 설정돼 있지 않습니다. 개발자는 커밋 전에 필수 명령을 실행해야 합니다.

<a id="records"></a>
## 기술 기록

문서는 현재 동작을 설명합니다. 변경 기록은 실제 변경과 검증을 설명합니다. 커밋 메시지와 코드 주석에는 주체, 동작, 대상, 결과를 직접 작성합니다. 필요한 원인은 한 문장으로 설명합니다. 영어와 한국어에는 같은 정보를 작성합니다. 비유, 의인화, 대화 경위, 개인 평가를 포함하지 않습니다.

올바른 코드를 유지합니다. 되돌림은 의도 차이만으로 결정하지 않고 정확성과 해로운 영향을 기준으로 결정합니다. 실제 변경 원인을 기록합니다. 서로 관련 없는 변경은 가능하면 별도 커밋으로 분리합니다.

외부 프로젝트 비교는 명시적으로 요청한 비교 보고서에서만 관리합니다. 현재 동작을 재현하거나 이해하는 데 필요한 의존성, 실행 검증 입력, 형식 명세는 해당 위치에서 식별할 수 있습니다.
