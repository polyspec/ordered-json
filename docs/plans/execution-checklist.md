# Execution checklist

## Wave 1 — Hosted CI that runs the full suite

| ID | Task | Deliverables | Verification | Done |
| --- | --- | --- | --- | --- |
| T1.1 | Track tasks in an execution checklist that the guards read: the guard of `make check`, the pre-push hook and the push gate read only the `partial` features of `docs/features.md`, so work that is not a product feature had no state that stopped a full run or a push. This checklist holds each task with one of the states `[ ]`, `[~]`, `[o]` and `[!] cause: <cause>; retry: <condition>`; `scripts/docs_check.py` rejects another state, a row without a task ID, a repeated ID, a checklist without rows and a translation whose IDs or states differ, and `scripts/full_run.py` and `scripts/push_gate.py` refuse while a task is `[~]` or the checklist cannot be read | `docs/plans/execution-checklist.md`(.ko), `scripts/docs_check.py`, `scripts/full_run.py`, `scripts/push_gate.py`, `AGENTS.md`(.ko) | `python3 scripts/test.py --unit test_docs_check test_full_run test_push_gate` | [o] |
| T1.2 | Run the checks offline and download only in `make tools`: cargo, go, npm and Composer ran online in every check, so `cargo build --locked` downloaded the crates of `rust/Cargo.lock` on demand, and the PIE PHAR and the supplementary suite were downloaded by hand. The Makefile exports `CARGO_NET_OFFLINE=true`, `GOPROXY=off`, `npm_config_offline=true` and `COMPOSER_DISABLE_NETWORK=1`, `scripts/toolchains.py` sets them for every entry point, and `make tools` runs with them removed (`$(ONLINE)`): it installs the Rust toolchain, npm, the crates (`cargo fetch --locked`), the PIE PHAR into `.cache/pie/pie.phar` and the supplementary suite into `.cache/JSONTestSuite`, each checked against `external-inputs.json` | `Makefile`, `scripts/toolchains.py`, `scripts/tests/test_toolchains.py`, `docs/operations/validation.md`(.ko), `AGENTS.md`(.ko) | `python3 scripts/test.py --unit test_toolchains` | [o] |
| T1.3 | Name `make tools` for a missing download: with the checks offline, a crate that `make tools` did not download failed with cargo's advice to retry without `--offline`, a missing PIE PHAR failed `make pie-check` with a `FileNotFoundError` traceback, and a missing supplementary suite failed with `--suite must contain test_parsing/` or `Supplementary suite is empty`. Every entry point runs `cargo fetch --locked --offline` for `rust/Cargo.lock` after the toolchain check and fails with the lock file, the first error line of cargo and `run make tools, which downloads them`; `scripts/check_pie.py` and `scripts/test.py` name the missing PHAR or suite and the `make tools` that installs it before any step | `scripts/toolchains.py`, `scripts/check_pie.py`, `scripts/test.py`, `scripts/tests/test_toolchains.py`, `AGENTS.md`(.ko) | `python3 scripts/test.py --unit test_toolchains` | [o] |
| T1.4 | Run the push gate of CI through its make target: the step of `.github/workflows/push-gate.yml` ran `python3 scripts/push_gate.py commit` directly, so the environment and the prechecks of the Makefile did not apply to it. `make push-gate COMMIT=<commit>` runs the gate and fails without `COMMIT`, and the step runs it | `Makefile`, `.github/workflows/push-gate.yml`, `scripts/tests/test_push_gate.py`, `AGENTS.md`(.ko) | `python3 scripts/test.py --unit test_push_gate` | [o] |
| T1.5 | Pin PHP by its minor release: no tracked file named the PHP of the checks, so a run on another PHP verified the tree with a PHP that no pin named, and CI could not take PHP from the repository. `.php-version` names 8.5, `scripts/toolchains.py` compares the major.minor of `php -n -r 'echo PHP_VERSION;'` with it and prints the expected and the actual version, and the records name the running patch release | `.php-version`, `scripts/toolchains.py`, `scripts/tests/test_toolchains.py`, `docs/operations/installation.md`(.ko), `AGENTS.md`(.ko) | `python3 scripts/test.py --unit test_toolchains` | [o] |
| T1.6 | Make the run of a commit its evidence instead of committed records: `docs/pie-verification.json` and `docs/verification.json` hashed every tracked file, so each commit made them stale, the guard of `make check` refused until a local `make pie-check` and `make check` regenerated and committed them, and a hosted CI that runs the full suite would be red after every commit. `make pie-check` and `make check` write `var/records/pie-verification.json` and `var/records/verification.json`, which Git ignores; the committed records are removed; `scripts/docs_check.py --records` checks the records of the checkout; the guard reads no record; a feature names `operations/validation.md#records` as its evidence | `scripts/verification_record.py`, `scripts/test.py`, `scripts/check_pie.py`, `scripts/docs_check.py`, `scripts/full_run.py`, `docs/features.md`(.ko), `docs/operations/validation.md`(.ko), `AGENTS.md`(.ko) | `python3 scripts/test.py --unit test_docs_check test_full_run` | [o] |
| T1.7 | Run the full suite in hosted CI with a report per job: hosted CI ran only the push gate, so the full suite of a commit ran only on a local machine. `.github/workflows/ci.yml` runs on every pushed commit of `main` and every pull request on `ubuntu-24.04` (no Python 3.9 build exists for `ubuntu-26.04`), with a matrix of the jobs `suite` (`hooks`, `pie-check`, `check`) and `docs` (`docs-check`, `owner-validate`) and `fail-fast: false`; every step runs a make target after a failure (`if: !cancelled()`), `make ci` (`scripts/ci_run.py`) runs every target to its end with a log per target, `make ci-summary` writes the job summary with the status, the time and the first failure lines of each failed target and copies the records, and the step `report` uploads `var/ci/<job>/` | `.github/workflows/ci.yml`, `scripts/ci_run.py`, `scripts/tests/test_ci_run.py`, `Makefile`, `scripts/push_gate.py`, `docs/operations/validation.md`(.ko), `docs/documentation-plan.md`(.ko), `AGENTS.md`(.ko) | `python3 scripts/test.py --unit test_ci_run test_failure_messages` | [o] |
| T1.8 | Test the rules of every workflow: nothing failed when a step ran a script or a tool directly, as the push gate did before T1.4, or when a job of `ci.yml` lacked its summary or report step. `scripts/tests/test_workflow_rules.py` reads every file of `.github/workflows` and fails, naming the file, the job and the step, when a step runs anything but one make target, when a job that runs `make ci` lacks `make ci-summary` or the upload of `var/ci/<job>/` under `if: ${{ !cancelled() }}` or has a step that does not run after a failure, when a matrix lacks `fail-fast: false`, and on `timeout-minutes` | `scripts/tests/test_workflow_rules.py` | `python3 scripts/test.py --unit test_workflow_rules` | [o] |
