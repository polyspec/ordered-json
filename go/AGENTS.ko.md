# 개발 절차

[English](AGENTS.md)

<a id="contract"></a>
## 계약과 문서

수정 전에 [사용 방법](README.ko.md)과 루트 저장소의 공통 JSON 계약을 읽습니다. 동작을 바꾸기 전에 공통 명세를 갱신합니다. 공식 사례와 기대 결과는 루트 저장소에서 관리하며 이 패키지에 독립 기대값을 추가하지 않습니다.

영어가 정본입니다. 한국어 문서에 같은 정보를 반영하고 전체 번역을 검토한 뒤 `source-sha256`을 갱신합니다. 문서는 [목록](docs/documentation-manifest.json)에 등록합니다. 개인 선호, 대화 맥락, 인증 정보, 백업 위치는 Git 외부에서 관리합니다. 주석과 커밋 메시지는 사실을 직접 작성합니다.

<a id="checks"></a>
## 필수 검사

~~~sh
make check
make docs-check
git diff --check
~~~

PR이나 소스 게시 전에 현재 후보에 공통 검사를 실행합니다. 추가 사례가 있으면 함께 검사합니다. Rust 코드를 변경하면 `cargo clippy --all-targets -- -D warnings`도 실행하고 Go 코드를 변경하면 `go vet ./...`를 실행합니다. 네이티브 소스를 변경하면 새로 빌드해야 하며 공통 네이티브 검사는 자동으로 다시 빌드합니다.

루트 registry가 이 패키지의 검증 명령을 정의합니다. 통합 결과는 같은 저장소 리비전의 모든 패키지에 적용됩니다. 테스트와 게시 상태는 별도로 기록하며, 현재 호스팅 CI는 설정되지 않았으므로 게시 전에 위 명령을 실행해야 합니다.

<a id="completion"></a>
## 완료

동작 변경에 문서와 변경 기록 수정을 포함합니다. 소스 게시는 별도로 확인하고 관련 개인 메모리를 Git 외부에서 갱신합니다. 기존 작업 승인을 따릅니다. 명시적 요청이 없으면 하위 에이전트에 위임하지 않습니다. 명시적 승인 없이 기존 이력을 재작성하지 않습니다.
